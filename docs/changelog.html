v0.9.2 — The Explorer Earns Its Keep

September 2026

A visual review of the Explorer on noupling's own code produced nine tickets, all fixed here; five analyzer bugs that made scores and Issues depend on things they should not are fixed too. noupling now audits itself at 100.0 with zero violations.

fix Explorer: a canvas you can read (#397–#405, #334, #335)

The friction: on a repo whose only top-level directory is crates/ the Explorer opened on one box; inferred one-directory layers stacked the LSM into a column with every edge drawn through the nodes in between; nothing ever fitted the canvas; Composition under issue focus showed exactly the modules that were not involved; critical and high badges were plain text; the header, Info tab, Levels and Matrix each counted differently; the Rules tab listed 28 pairwise rows for 8 layers with the targets cut off.

The fix: the Explorer opens at the first level that branches and labels collapsed chains (noupling-cli / src); edges are routed in lanes beside the tiers with fan-out slots and same-tier arcs, wide tiers wrap into rows, and the canvas fits its content on every scope or view change; Composition and the LSM show the participants at full strength and dim the rest; directory metrics come from the audit and files and LOC roll up; band chips have their colours; the Rules tab shows the layer stack once. The Force view is removed (#396; Data Contract format_version 3).

fix One score formula (#354)

Layer filtering used to run last and re-score on the severity sum, so a layered project and an unlayered one with the same graph scored 96.7 and 66.7. Now the pipeline decides the violation set, then scores it once on TRI — for --diff-base runs too. Layered projects' scores change on upgrade; re-check --fail-below.

fix Analyzer findings that were about the analyzer (#413, #414, #357, #355)

  • Abstractness counts module-level functions as concrete (TypeScript, Rust, Kotlin), so a directory of components is no longer "100% abstract".
  • The Stable Dependencies check skips a directory and its own ancestor; lib.rs → analyzer/ is composition, not a violation.
  • Monorepo audits run the shared pipeline per module — layers, rules, risk weights — and the summary lists each module's Issue cards, so audit, audit --module and report --module agree.
  • Layer inference is sticky: the layers a snapshot infers are recorded and kept while a fresh detection finds nothing and they still cover 15% of files, so one commit near the 30% line no longer flips the audit's mode.

refactor noupling on itself (#412)

The Explorer template's components ↔ state cycle is broken and its layers are declared in .noupling/settings.json, so the repo's own audit is clean and CI enforces the order. Practice what you audit.

v0.9.1 — Dogfooding Fixes

September 2026

Eight things found by running the released 0.9.0 on noupling itself and on the examples/ projects: one band that contradicted its own score impact, three counts that disagreed between a header and the cards or between a parent page and its child, and a handful of cosmetics.

fix A band never contradicts its score impact (#379)

The friction: On a five-module project the only Cycle read [LOW] Cycle … Score impact: 40.0. The severity ladder is mostly a depth measure, so a shallow ring on a small codebase was "low" while costing 40 of 100 points — and the pr comment and Sonar import called it low too.

The fix: Coupling Violations and Cycles are now floored by the points they cost: 10 is critical, 5 at least high, 1 at least medium. Large projects are unaffected (noupling's own 28 Issues keep their bands). The Explorer's per-node violation rows, which had a private three-step ladder, now show the band of their owning Issue.

fix Counts that agree with the cards (#380, #381)

  • critical_violations in JSON and XML counted ring hops above the threshold as extra violations. It is now the number of Coupling Violation and Cycle cards whose band is critical.
  • Directory pages in html and md (and directory_tree in JSON) roll violation counts up to every ancestor, so a row marked ! never shows 0. violations_count is now a subtree count.

fix Reports and CLI (#382, #383, #384, #386)

  • report --format all includes the Explorer, as the help promised (14 reports); the --format help keeps its per-format lines.
  • The html and md writers clear their own previous pages before regenerating, so pages for renamed or removed source directories no longer linger.
  • trend prints 0.0 instead of +0.0 for float-noise deltas and labels its timestamp column UTC.
  • Baseline summaries say not in baseline instead of new, so they can no longer be confused with the Violation Age new bucket two lines below.

docs Examples with expected output (#385)

examples/README.md explains the three Kotlin projects and what each should report; kotlin-coupled now demonstrates a Coupling Violation instead of a second Cycle, and a CLI test keeps all three honest. Linked from the How-to page.

v0.9.0 — Same Issues in Every Report

September 2026

feat One Issue type, nine kinds, every report (#338 epic)

The friction: Each report format cherry-picked from the audit result. The text report listed coupling violations and cycles; JSON had some kinds, XML fewer, Sonar only cycles; the Explorer silently re-audited with different settings; rule and layer violations never reached JSON; and the same Red Flag was worded three different ways. You could not compare two formats and be sure they described the same codebase.

The implementation: noupling-core gains an Issue type with one variant per kind — Coupling Violation, Cycle, Rule Violation, Layer Violation, Gravity Well, Red Flag, Stability Violation, Zone Flag, Low Cohesion — and an issues() accessor in canonical order (severity band, kind, subject). Every Issue is an Issue card: kind, band (critical / high / medium / low, assigned once), subject, a one-sentence reason with this instance's numbers, a recommendation, and its score impact, all written once in core (#340, #342). A ring is one Cycle, never also its edges. Then every format was moved onto it:

  • text renders Issue cards under Issues (N) with a Points lost breakdown that adds up (#340, #342).
  • json gains the single issues array; xml and sonar derive from it — Sonar now imports all nine kinds as noupling:<kind> (#344).
  • html and md render cards for all nine kinds: the root page with per-kind counts, each directory page with only the Issues anchored under it (#346).
  • dashboard gets a nine-tile kind row and a full Issue table; pr names every kind with a count and lists the top five; briefing ranks its top ten by score impact with core's recommendations verbatim (#347).
  • mermaid, dot and bundle accent every edge-shaped Issue with a per-kind style and a legend, one edge per pair and kind (#348).
  • strategy trends the Issue count per kind across snapshots, recorded at scan time; older snapshots show as gaps (#349).
  • explorer reads Issues from the shared array (Data Contract format_version 2): the Issues tab, verdict text, score breakdown, Rules offenders and focus mode all come from core; baselined Issues are dimmed and marked accepted (#345).

The contract: the per-kind JSON arrays are removed and the coverage test asserts the format-class rule from CONTEXT.md against each format's data (#350, ADR 0002). Breaking for JSON/XML consumers — the changelog carries the field mapping.

feat One audit per snapshot (#341, ADR 0001)

Layer inference and the actionable coupling-mode fallback move from the Explorer into the shared audit pipeline, so audit, every report and the CI gate see the same layers and the same Issues. Projects without configured layers will see their score change (usually upward); "infer_layers": false turns inference off (#356). Inferred globs now match the path segments that produced them, and never produce <unlayered> violations.

feat Baseline over every Issue kind (#343)

baseline save records every current Issue; --baseline is accepted by both audit and report, keeps accepted Issues visible and marked instead of dropping them, and fails only on new ones. Identities are stable across scans (directory pair for Coupling Violations and Red Flags; canonically rotated rings for Cycles). Re-run baseline save after upgrading. New report --format text.

Also in this release:

  • fix critical_severity is honoured again as the step to the critical band (#368).
  • fix Headline Violations: counts agree with the Issue cards everywhere (#358).
  • fix Deterministic output across scans: representative edges, ring rotation and hop files no longer depend on per-scan module ids (#367, #370).
  • fix Scan-time trend records survive --diff-base; --module runs never overwrite them (#370).
  • fix Explorer: focusing a gravity well shows the well and the modules pulling on it (#333).
  • tests tests/fixtures/every_issue_kind produces all nine kinds; issue_coverage.rs is the format-class contract (#339, #350). 376 tests total.
  • docs CONTEXT.md glossary, two ADRs, a Findings section and Issue-card schema on the docs site, README and llms.txt refreshed (#337, #351).

v0.8.0 — The Explorer Release

September 2026

feat Explorer: noupling report --format explorer (#228)

The friction: Every existing report answers "how healthy is this codebase?" with a number and a list. None of them let you read the architecture: see the layers, follow an edge, drill into a package, and understand why a specific dependency is a problem. Onboarding developers, architects reviewing an unfamiliar system, and anyone weighing a refactor were all left to reconstruct the picture from tables.

The implementation: A new noupling-explorer crate serializes a versioned Data Contract (modules, edges, cycles, violations, gravity wells, red flags, per-file LOC / Ca / Ce / I / blast radius, score breakdown, snapshot history) and embeds it in a single self-contained HTML file built from a React + Tailwind template that CI drift-checks. Roughly seventy PRs (#244–#300) across the summer:

  • Layered Structure Map — the primary canvas. Packages and files by layer, edges between them, distinct accents for violations, cycles, and selection. Click to select, double-click to drill, breadcrumb to scope out. Unlayered codebases get synthetic tiers; if .noupling/settings.json has no layers, they're auto-detected and a banner offers a copy-paste config snippet (#260, #266, #267).
  • Side panel — Info (score front and centre), Issues (every problem in scope as an actionable list with focus mode, #265, #275), Rules (click a broken rule to filter, again to jump to the first offender, #268, #269), Files (expand-on-click tree with in-tab breadcrumb, #273), Levels (Finder-style one-level drill-down, #274).
  • Details inlay — selecting a node or edge opens an inlay column with metrics, an "About this verdict" explainer (#276), cycle break edges with weight contrast (#277), and click-to-source links honouring --editor vscode|jetbrains|sublime|cursor.
  • Alternate views — Matrix (bounded at ≤200 nodes, clickable cells), Force (d3-force with Rust-precomputed cluster boundaries, #278), Composition (#279), plus path-finder and min-cut overlays.
  • Score breakdown dialog (#270) and a history scrubber over up to 12 snapshots (#271; --no-history to shrink the file).
  • LLM enrichment v1 (#280) — optional per-module summaries from .noupling/enrichment/modules.json.

The ripple effect: The repo became a Cargo workspace — noupling-core / noupling (cli) / noupling-explorer — with the dependency direction enforced both by the compiler and by noupling's own dependency_rules (#229). Known gaps from a critical review are tracked in #315; this is the v1 "interactive readme", with sandbox editing (v2) still to come.

feat Martin's package metrics: A, I, and D (#69, #68, #70)

Per-directory Abstractness (A = abstract / (abstract + concrete), from trait/interface/abstract-class counts in Rust, Java, Kotlin, TypeScript), Instability (I = Ce / (Ca + Ce)), and Distance from the Main Sequence (D = |A + I − 1|). Directories with D > 0.5 are flagged as Zone of Pain (stable + concrete) or Zone of Uselessness (abstract + unstable). New Stable Dependencies Principle violations flag a more-stable directory depending on a less-stable one. All three surface in text, JSON, and HTML reports.

feat Cohesion, reworked around logical nodes (#223)

Directories are now classified as Container (only subdirectories; cohesion is null) or Package (has files). For Packages, each direct child — file or subdirectory — is one logical node and cohesion is the fraction of file-level edges crossing between them, so grouping folders stop being mis-flagged as low-cohesion. Implemented behind a reusable LogicalNodeIndex. JSON consumers: handle "cohesion": null and the new kind field.

refactor Deepening pass over the reporter and Explorer state

Twelve behaviour-preserving PRs (#309–#327): the audit pipeline folded into one module, a DatabaseSession seam, a ReportFormatter trait + registry that now covers every non-bespoke format (the all arm simply enumerates it), data::Report carved out with each format as its own sibling file, and on the template side state/queries.ts, an IssueFocus module, a HighlightPolicy behind the canvas, and SidePanel split per tab.

Also in this release:

  • fix Layered source → unlayered target is now reported as a violation with to_layer = "<unlayered>" instead of being silently dropped (#220). Existing layers configs may surface new violations after upgrading.
  • fix Import resolvers matched on path-segment boundaries instead of substrings; import re no longer produces a phantom structure.py → structure.py self-edge (#212).
  • infra Distribution is Homebrew + GitHub Releases only; crates.io publishing dropped (#329). Build from source with cargo install --path crates/noupling-cli.
  • infra release.yml now chains into the Homebrew tap update via repository_dispatch (#210).
  • tests Playwright smoke suite for the Explorer template runs in CI; a manual regression suite targets real codebases (#261). 310 tests total.
  • docs llms.txt moved to docs/ so it's served at the canonical Pages URL.

v0.7.0 — Architectural Deepening + Elixir/Scala

May 2026

refactor Deepening pass: collapse, split, relocate

The friction: The codebase had grown a few god files. src/analyzer/mod.rs was 2,955 LOC mixing cycle detection, scoring, gravity wells, red flags, layers, rules, and metrics. src/main.rs was 988 LOC of CLI handlers that each spelled out the same 5-step apply_*/filter_* incantation on AuditResult. JSON sidecar files (diff-meta.json, suppressed.json, external.json) wrote the scan→audit contract through the filesystem. 14 per-language parsers lived as 14 free functions in two large shared files. The tool flagged a reporter ↔ analyzer red flag on its own audit.

The implementation: Six PRs, no behavior change.

  • #192 introduced analyzer::audit_with_settings(modules, deps, &settings) as the canonical seam. Six call sites collapsed to one each.
  • #193 deleted the JSON sidecars. suppressed_count, diff_base, and diff_changed_files are now columns on the snapshots table; external-dep counts live in a new snapshot_external_deps table. Existing databases auto-migrate via ALTER TABLE…ADD COLUMN.
  • #194 introduced the LanguageParser trait. Each language is now a self-contained adapter at src/scanner/parsers/<lang>.rs. Adding a language = one new file + one registry line.
  • #195 split src/analyzer/mod.rs into 15 concern files (cycles, coupling, metrics, cohesion, independence, gravity_wells, red_flags, layers, rules, violation_age, critical_path, actions, monorepo, tests, mod). The orchestrator is <330 LOC; no concern file exceeds 540 LOC.
  • #196 moved run_* handlers into src/commands/. main.rs shrank from 988 LOC to 72. Added the first end-to-end integration test at tests/cli.rs.
  • #198 moved DependencyDirection from core (where it was misplaced as a scanner primitive) to analyzer/direction.rs where it belongs. Eliminated the analyzer ↔ core red flag.

The ripple effect: Self-audit went from 1 red flag to 0. Test count grew from 195 to 213 unit tests. The reporter still depends on the analyzer, but on specific concerns rather than a fat AuditResult struct.

feat Elixir & Scala parsers (#89, #88)

Total supported languages now 16. Both adapters were added in 6 file changes (no trait modification, no dispatch changes, no other adapter touched)—empirical proof that the LanguageParser seam from #194 was correctly shaped.

remove JSON sidecar files in .noupling/

diff-meta.json, suppressed.json, and external.json are no longer written. Snapshot metadata is fully in SQLite. Existing databases migrate forward automatically.

Also in this release:

  • docs llms.txt at the repo root for AI/LLM-friendly project documentation (#141)
  • tests 4 new CLI integration tests covering --fail-below exit codes and report-format contracts. Total 218 tests (213 unit + 5 integration), up from 195.
  • infra Opt-in pre-commit hook at .githooks/pre-commit running cargo fmt --check + cargo clippy. Enable with git config core.hooksPath .githooks.
  • infra CI architecture-audit threshold raised from --fail-below 80 to --fail-below 95. Future PRs that drop the project's own health below 95 will fail.

v0.6.0 — The Risk Framework Release

April 2026

feat Software Dependency Risk Framework (#167)

The friction: All coupling violations were scored by depth alone. A sibling dependency at depth 2 scored the same whether it was a harmless utility import or a dangerous architectural shortcut. There was no way to distinguish the risk level of different dependency types.

The implementation: Every dependency is now classified by direction: Downward (↓ weight 2), Sibling (↔ weight 4), Upward (↑ weight 6), Circular (↻ weight 10). The Relationship Risk Index (RRI) combines direction weight with density (import count). The Total Risk Index (TRI) sums all RRIs to derive the health score. Weights are configurable in settings.json.

The ripple effect: Teams can now see why a dependency is risky, not just that it exists. The same import count between two modules produces RRI 8 for a sibling pair vs RRI 20 for an upward dependency. Refactoring priorities become self-evident.

feat Gravity Well detection (#171)

Modules with aggregate RRI exceeding 2× the project median are flagged as “Gravity Wells”—God Objects that pull the system into their orbit. Includes per-direction RRI breakdown to show which dependency types contribute most.

feat Architectural Red Flags (#172)

Two anti-pattern detectors: Fused Sibling (sibling pair with density > 2× median—should be merged or extracted) and Trapped Child (module with upward dependencies—cannot be reused independently).

feat Per-level cycle visualization in bundle sunburst

Cycle participants at the current zoom level turn red. The weakest hop (fewest imports) is highlighted with a “break this side” tooltip. Hovering a cycle edge dims everything else.

Also in this release:

  • feat Default coupling mode changed to “strict”—sibling coupling now affects the score
  • feat Metrics Guide in HTML and Markdown reports
  • feat Direction badges (↓↔↑↻) and RRI values in all report formats
  • feat RRI-based Sonar severity mapping
  • feat Dashed red edges for circular deps in Mermaid/DOT
  • feat External dependency tracking (scanner counts unresolved imports as third-party deps)
  • feat Layer-specific thresholds (allow_sibling, max_sibling_density, reduced_sibling_weight)
  • feat N-cycle detection (3+ node cycles)

v0.5.0 — The Tech Lead Release

April 2026

feat Interactive Technical Leader Dashboard (#132)

The friction: Engineers got rich, drillable HTML reports. CTOs and tech leads got... numbers in a terminal. The existing reports answered "where are the violations?" but not "is the architecture improving?", "which module is the riskiest to change?", or "what should we refactor first for the biggest impact?"

The implementation: A self-contained HTML dashboard combining all v0.5.0 metrics: score badge, sortable scorecard table, risk matrix scatter plot (instability vs blast radius), zoomable sunburst with health-score colors and dependency edges, violation breakdowns by age and type, quick-win refactoring targets, and the dependency depth critical path.

The ripple effect: noupling becomes presentable to executive audiences. The dashboard is the artifact you put in a quarterly review slide deck. Generate it, screenshot it, send it.

feat Module independence score (#126)

Per-module ratio of internal to total dependencies. Answers "Can team X own this module independently?" A module with 95% internal deps is ready to extract; one with 40% is deeply entangled.

feat Blast radius metric (#127)

For each module, the count of other modules transitively affected by changes. BFS on the reverse dependency graph. Top 10 highest blast radius shown in audit. Critical for change risk assessment.

feat Instability metric — Martin's I (#128)

Classic I = fan_out / (fan_in + fan_out). Includes Zone of Pain detection: stable modules (I < 0.3) with high fan-in are foundational but hard to change.

feat Coupling trend per area (#129)

The --by-module flag on the trend command shows per-directory health scores across snapshots, with +/- indicators. "The payment module went from 82 to 67 over the last 6 sprints" — now visible.

feat Dependency depth and critical path (#130)

The longest transitive dependency chain in the project, computed via topological sort. Deep chains mean changes ripple through many layers.

feat Violation age tracking (#131)

Compare current violations against historical snapshots. Classify as new (regressions), recent (2–4 snapshots), or chronic (5+). Helps prioritize urgent fixes vs accepted debt.

feat --format all (#140)

Generate every report format in a single command: noupling report . --format all. Useful for CI pipelines that publish multiple artifacts.

v0.4.1 — The Visualization Release

April 2026

feat Sunburst dependency visualization (#123)

The friction: Existing reports showed violations as lists and tables. Teams couldn't see the overall shape of their architecture—where coupling clusters lived, how dependencies flowed between layers, or which areas were cleanly separated.

The implementation: A zoomable D3.js sunburst where concentric rings represent the directory hierarchy, color-coded by health score. Curved dependency edges connect inner ring segments, aggregated from all children underneath (using D_acc). Click any segment to zoom in with a smooth 750ms animated transition. Click the center to zoom back out. Edge hover tooltips show the exact from/to connection and import count.

v0.4.0 — The Architecture-Aware Release

April 2026

feat Monorepo support (#84)

The friction: Large codebases with multiple modules (app, lib-core, lib-network) were analyzed as a single blob. A coupling violation in lib-core dragged down the score for the entire repo, making the number meaningless for teams that owned individual modules.

The implementation: Each module defined in settings.json gets independent D_acc computation, BFS coupling detection, and cycle finding. Cross-module imports are validated against a declared depends_on graph. The overall score is a weighted average by file count.

The ripple effect: Teams can now own their module's health score independently. The --module flag lets CI pipelines gate on individual modules, and cross-module violations make implicit dependencies explicit.

feat Inline suppression (#73)

The friction: Some coupling is intentional. A data layer importing a domain entity for mapping is architecturally correct in many patterns, but noupling flagged it. Teams had no escape hatch short of disabling the tool.

The implementation: // noupling:ignore on the import line (or the line above) excludes that dependency from analysis. Works with //, #, and -- comment styles. The suppressed count is tracked and reported so suppressions don't become invisible.

The ripple effect: Teams can adopt noupling incrementally without false-positive friction, while the suppressed count prevents noupling:ignore from becoming the new @SuppressWarnings("all").

feat XS metric — weakest link analysis (#112)

The friction: Circular dependencies were detected and scored, but the output didn't answer the practical question: "which import should I remove first?" Teams saw a cycle of order 5 and didn't know where to start.

The implementation: For each circular dependency, track import counts per hop. The hop with the fewest imports is the weakest link—the cheapest edge to cut. total_xs sums all imports needing removal across all violations.

The ripple effect: Refactoring is now prioritizable. A cycle with break cost 2 is a 10-minute fix. One with break cost 128 is a planned effort. The HTML report shows per-hop XS counts in expandable details.

feat Architectural layer enforcement (#92, #110)

The friction: Clean architecture projects (presentation → domain → data) had dozens of "violations" that were actually correct downward dependencies. The noise made real violations invisible.

The implementation: Define ordered layers in settings.json. Dependencies flowing downward are suppressed from coupling violations. Upward dependencies (data → presentation) are flagged as both coupling and layer violations.

feat Custom dependency rules (#91)

Glob-based allow/forbid rules for specific import patterns. Enforce boundaries like "UI must not import data layer directly" with custom messages.

feat Per-directory cohesion scoring (#64)

Measures how much files within a directory depend on each other. Low cohesion flags directories that group unrelated code—candidates for splitting.

v0.1.0 — The Foundation

April 2026

feat Core architecture

The problem: Most linters check code style. Nothing checks whether your modules actually maintain the boundaries you drew on the whiteboard.

The approach: Four-stage pipeline: scan (discover + parse via Tree-sitter), store (SQLite snapshots), analyze (D_acc + BFS + DFS cycle detection), report.

Key algorithm: D_acc (accumulated dependencies) is computed bottom-up: for each directory, union all external dependencies from its subtree. BFS walks the tree top-down checking sibling pairs. Circular dependencies are found via DFS on sibling adjacency graphs.

  • Rust parser with Tree-sitter
  • SQLite storage with snapshot history
  • Severity scoring: weight / (depth + 1)
  • Health score: 100 × (1 - sum / total)
  • Configurable settings with auto-creation
  • Cross-platform CI (Linux, macOS, Windows)
